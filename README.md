# Knowledge Assistant · Build specification (2)

Knowledge Assistant · Build specification Page 1 Knowledge Assistant Build "Knowledge Assistant": an enterprise RAG chatbot that answers employees' questions from a shared company knowledge base, citing its sources. Stack FastAPI (Python 3.12) + SQLAlchemy, SQLite locally / Postgres + pgvector in production; React + TypeScript + Vite + Tailwind; Google Gemini; Tesseract OCR. One command starts everything locally. Features  Sign-in: – Email + password; create account (admins can turn this off); change password. – Passwords hashed with bcrypt; HTTP-only session cookie. Make its Secure flag a setting, off for local http. – 5 failed sign-ins in 15 minutes locks that email for 15 minutes; one generic error for wrong email or password. – The first account is the admin. Admins manage users: add, disable, make/remove admin, reset password.  Knowledge base: – Upload PDF, DOCX, TXT, MD (up to 25 MB), shared with everyone, processed in the background. – Status: processing / ready / failed with a readable reason; the page updates live. – Stat tiles, an upload dropzone, and a document table with search, filters, download and delete.  Reading files: – PDF text with pypdf; DOCX paragraphs AND tables. – A PDF page with almost no text is treated as a scan and read with local Tesseract OCR. The app still works if Tesseract isn't installed.  Chunking: about 1,000 characters with 150 overlap, breaking only in the second half of each window, so chunk counts stay sensible.  Chat: – Search the documents first (Gemini embeddings, 768 dimensions; cosine similarity threshold 0.62). – Stream the answer live, with numbered source chips that open a side panel. – If nothing matches, answer from general knowledge with a "not from your documents" badge. – Copy, read aloud, regenerate and stop. – Private chat history grouped by date, with search and delete.  Gemini: – Key in a gitignored backend/.env, never logged; models configurable (Flash-Lite for answers). – First words in about 2

Generated by the Quorq AI SDLC platform. Two applications, one repository:

- **`frontend/`** -- the approved app design as a Vite + React SPA. Every screen
  was reviewed and approved, and runs on seeded sample data.
- **`backend/`** -- a FastAPI service. No architecture had been approved
  when this repository was created, so it starts with its health check and
  nothing else.

## Running it

```bash
cd frontend
npm install
npm run dev
npm test          # unit tests (Vitest)
npm run lint       # ESLint
npm run format     # Prettier
```

```bash
cd backend
pip install -r requirements.txt
uvicorn app.main:app --reload
pytest
ruff check .
ruff format .
```
